1. Storytime: The Birth of Operating Systems

Before we dive into commands and internals, it helps to know where modern operating systems came from. The story matters because the design choices behind Unix, GNU, Linux, Windows, and macOS still shape the tools defenders use every day.

Before Personal Computers

1960s-1970s

Imagine a world where computers filled entire rooms. You could not just sit down and "use" a computer: you had to submit punch cards and wait hours (sometimes days) for your results. These were the mainframe days, and computing was reserved for universities, governments, and massive corporations.

In 1969, at AT&T's Bell Labs, an important shift happened. Ken Thompson and Dennis Ritchie created Unix, an operating system written in the C programming language (which Ritchie also invented). Unix was elegant, portable, and introduced concepts we still use today: hierarchical file systems, pipes, and the shell.

Context: Unix was originally a play on words from "Multics" (another OS project). Where Multics tried to do everything, Unix focused on a few ideas and did them well.

Enter Richard Stallman (1983)

September 27, 1983

Richard Stallman, a programmer at MIT's AI Lab, was furious. Software was becoming proprietary. Companies locked away their code. You couldn't study it, modify it, or share it. For Stallman, this was a moral crisis.

So he did something radical: he announced the GNU Project. His mission? Create a complete, free (as in freedom) operating system.

"I consider that the Golden Rule requires that if I like a program I must share it with other people who like it."
Richard Stallman, GNU Manifesto (1985)

GNU stood for "GNU's Not Unix", a recursive acronym. Stallman and his team created GCC (the compiler), Bash (the shell), Emacs (the text editor), and countless utilities. They built almost everything needed for a complete operating system.

Almost. They were missing one critical piece: the kernel.

The Finnish Student Who Changed Everything (1991)

August 25, 1991

A 21-year-old computer science student in Finland named Linus Torvalds posted this message to a Usenet newsgroup:

Linus described his project as a free operating system for 386/486 AT clones and called it "just a hobby."
Linus Torvalds, Usenet announcement (1991)

That small hobby project became one of the most important kernels in modern computing.

Linus had created a kernel, the missing piece of GNU. When combined with all the GNU tools Stallman's team had built, you had a complete, free operating system: GNU/Linux.

The Impact Today:
- Linux is a standard platform for servers, cloud infrastructure, and security tooling
- Many high-performance computing systems use Linux because it is flexible and scriptable
- Android is built on the Linux kernel
- Network appliances, lab machines, and incident response environments often rely on Linux
- Learning Linux helps you understand logs, permissions, processes, and networking at a practical level

Two different efforts, GNU's userland tools and Linux's kernel, came together into a system that now powers servers, cloud platforms, Android devices, security labs, and a huge part of modern infrastructure. That is why Linux keeps showing up in cybersecurity training.

Meanwhile, in the Corporate World: Microsoft's Journey

1981

IBM needs an OS for their new personal computer. Bill Gates licenses MS-DOS to them and keeps the rights to sell it to other manufacturers. This decision makes Microsoft.

1985

Windows 1.0 launches as a graphical shell running on top of DOS. It's clunky, but it's the beginning.

1995

Windows 95 changes everything. The Start menu, taskbar, and 32-bit architecture. Microsoft dominates the desktop.

2001

Windows XP merges the consumer (9x) and business (NT) lines. It becomes legendary for its stability and longevity.

2015 -> 2021

Windows 10 brings "Windows as a Service." Then Windows 11 arrives with a modern UI and native Android app support, plus WSL: Windows Subsystem for Linux. Microsoft finally embraced Linux.

Apple's Transformation: From Mac OS to macOS

1984

The original Macintosh launches with the classic "Mac OS", a revolutionary GUI that influenced everything after it.

2001

Apple releases Mac OS X, built on Darwin, a Unix-based kernel derived from BSD and Mach. Suddenly, Macs had the power of Unix under the hood.

2020

macOS Big Sur arrives alongside Apple's M1 chip, ARM-based silicon that fundamentally changes the game for performance and efficiency.

The Mobile Revolution: Android's Linux Heart

2003

Android Inc. is founded. Their secret weapon? Building on the Linux kernel.

2005

Google acquires Android. They see the future of mobile.

2008 -> Today

First Android phone launches. Today, Android is one of the dominant smartphone operating systems globally, and its Linux base matters when you study mobile security.

Why This Matters for Cybersecurity:
  • Open source means auditable code: you can inspect what Linux is doing instead of only trusting a vendor.
  • Lineage affects vulnerabilities: Windows issues often look different from Unix-style issues.
  • Attack surfaces vary: servers, endpoints, and mobile devices expose different services and defaults.
  • Windows endpoints are common enterprise targets: defenders need to know that environment well.

2. What is an Operating System?

Now that you know the history, let's understand what an operating system actually does. At its core, an OS is the layer between you and the hardware.

USER (You)
|
APPLICATIONS (Browsers, Tools, Games)
|
OPERATING SYSTEM (Kernel + System Services)
|
HARDWARE (CPU, RAM, Disk, Network)

The OS as a Translator

When you click "Save" in a document, you don't manually tell the hard drive to write specific bits to specific sectors. The operating system handles that translation.

Your application says: "Save this file"

The OS translates it to: "Write these bytes to sectors 34892-34910 on disk 0, update the file table, set permissions, record the timestamp..."

Kernel Space vs User Space

Kernel Space User Space
Full hardware access Limited, controlled access
Operating system core (kernel) Applications, user programs
Device drivers Browsers, games, tools
Crash here = system crash (BSOD, kernel panic) Crash here = app closes, system continues

System Calls: The Bridge

Applications in user space can't directly access hardware. They must request services through system calls, the official API between user space and kernel space.

Common System Calls:
- open(), read(), write(), close(): file operations
- fork(), exec(), exit(): process management
- socket(), bind(), connect(): networking
- mmap(), brk(): memory management

3. Virtualization & Modern Concepts

Modern computing isn't just about one OS on one machine anymore. Understanding these concepts is critical for cybersecurity work.

Concept What It Is Use Case
Bare Metal OS installed directly on physical hardware Daily driver, production servers, gaming
Virtualization OS running on virtual hardware (VMs) Labs, malware analysis, testing
Type 1 Hypervisor Runs directly on hardware (ESXi, Hyper-V) Enterprise servers, data centers
Type 2 Hypervisor Runs on host OS (VirtualBox, VMware Workstation) Home labs, development
WSL / WSL2 Linux kernel running inside Windows Best of both worlds, development
Containers Isolated processes sharing the host kernel (Docker) Deployment, microservices, CI/CD

Why Virtualization Matters for Security

Lab Safety

Malware Analysis

Detonate malware safely in isolated VMs. Take snapshots. Analyze behavior. Restore. Repeat.

Practice Range

Penetration Testing Labs

Build vulnerable networks (DVWA, Metasploitable) without risking real systems.

Forensics

Incident Response

Capture and analyze disk images in isolated environments for forensics.

WSL2: A Game Changer

Windows Subsystem for Linux 2 runs a real Linux kernel inside Windows. You get native Linux performance with full Windows integration. 

# Install WSL2 from PowerShell (Admin)
wsl --install

# List available Linux distros
wsl --list --online

# Install Ubuntu
wsl --install -d Ubuntu

# Enter your Linux environment
wsl

4. Core OS Functions (Practical Skills)

Every operating system handles these five core functions. As a security professional, you need to know how to inspect, manage, and manipulate each one across all major platforms.

4.1 Process Management

A process is a running instance of a program. Every application, service, and malware sample runs as a process. Knowing how to find, analyze, and kill processes is fundamental.

Viewing Processes

Windows
# Task Manager (GUI)
taskmgr

# Command line - list all processes
tasklist

# PowerShell - detailed process info
Get-Process

# Find process by name
Get-Process -Name "chrome"

# Find by PID
Get-Process -Id 1234
Linux
# List all processes
ps aux

# Interactive process viewer
top
htop  # Better version

# Find process by name
ps aux | grep nginx

# Process tree
pstree

# View /proc filesystem
ls /proc/[PID]/
macOS
# Activity Monitor (GUI)
open -a "Activity Monitor"

# Command line
ps aux

# Top processes
top

# Find process
ps aux | grep Safari

Killing Processes

Windows
# Kill by name
taskkill /IM notepad.exe

# Force kill by PID
taskkill /F /PID 1234

# Kill and all child processes
taskkill /F /T /PID 1234

# PowerShell
Stop-Process -Name "chrome" -Force
Stop-Process -Id 1234 -Force
Linux
# Graceful terminate (SIGTERM)
kill 1234

# Force kill (SIGKILL)
kill -9 1234

# Kill by name
killall nginx
pkill nginx

# Kill all processes of user
pkill -u username
macOS
# Same as Linux
kill 1234
kill -9 1234

# Kill by name
killall Safari

# Using pkill
pkill -f "process name"
Security Relevance:
  • Malware often spawns multiple processes, so learn to identify and kill process trees.
  • Look for unusual parent-child relationships, such as Word spawning PowerShell.
  • Check for processes with high privileges, such as SYSTEM or root, when they should not have them.
  • Tools like Process Monitor on Windows reveal what processes are doing.

4.2 Memory Management

The OS manages RAM allocation, virtual memory, and swap space. Understanding memory is crucial for forensics and exploit development.

Windows

  Select FreePhysicalMemory,
         TotalVisibleMemorySize

# Process memory

  Select -First 10
Linux
# Memory info
free -h

# Detailed from proc
cat /proc/meminfo

# Process memory map
pmap [PID]

# Memory top
top -o %MEM
macOS
# Memory pressure
vm_stat

# Memory usage
top -o mem

# System profiler
system_profiler SPHardwareDataType

4.3 File System Management

File systems determine how data is stored, organized, and secured on disk.

OS Primary File System Key Features
Windows NTFS ACLs, Alternate Data Streams, journaling, encryption (EFS)
Linux ext4 / xfs / btrfs Unix permissions, ACLs, extended attributes
macOS APFS Snapshots, encryption, space sharing, clones

File Permissions

Windows (NTFS ACLs)
# View permissions
icacls C:\path\to\file

# Grant permission
icacls file.txt /grant User:F

# Remove permission
icacls file.txt /remove User

# Inheritance
icacls folder /inheritance:r
Linux (Unix Permissions)
# View permissions
ls -la

# Change permissions (rwx)
chmod 755 script.sh
chmod u+x file

# Change owner
chown user:group file

# Special bits
chmod u+s program  # SUID
chmod g+s folder   # SGID
chmod +t folder    # Sticky
macOS
# Same as Linux
chmod 755 script.sh
chown user:group file

# Extended attributes
xattr -l file
xattr -d attr file

# ACLs
chmod +a "user:admin allow write" file

5. Windows Internals Deep Dive

Windows is common across business endpoints, so attackers study it closely. Understanding its internals is important for security professionals.

NTFS: The Windows File System

Master File Table (MFT)

The MFT is the heart of NTFS. It's a database containing entries for every file and directory, including metadata, timestamps, and data locations.

MACB Timestamps:
- Modified: content last changed
- Accessed: file last opened
- Changed (MFT): metadata last changed
- Born: file creation time

Attackers often try to modify these (timestomping) to hide activity!

Alternate Data Streams (ADS)

NTFS allows multiple data streams per file. Attackers can abuse this feature to hide payloads. 

# Create hidden stream
echo "hidden data" > normal.txt:hidden.txt

# View streams
dir /R
Get-Item .\normal.txt -Stream *

# Read hidden stream
Get-Content .\normal.txt -Stream hidden.txt

# Check all files in directory for streams
Get-ChildItem -Recurse | ForEach-Object { Get-Item $_.FullName -Stream * }

Windows Registry

The registry is a hierarchical database storing OS and application configuration. It matters for forensics because it records settings, startup entries, user activity, and persistence points.

Hive Content File Location
HKEY_LOCAL_MACHINE (HKLM) System-wide settings C:\Windows\System32\config\
HKEY_CURRENT_USER (HKCU) Current user settings C:\Users\{user}\NTUSER.DAT
HKEY_USERS (HKU) All user profiles Aggregated from user hives

Common Persistence Locations

# Run keys (execute at login)
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
HKLM\Software\Microsoft\Windows\CurrentVersion\Run
HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce

# Services
HKLM\SYSTEM\CurrentControlSet\Services

# Scheduled Tasks
C:\Windows\System32\Tasks\

# Query via PowerShell
Get-ItemProperty "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run"
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"

Windows Services

# List services
Get-Service
sc query

# Start/Stop service
Start-Service -Name "ServiceName"
Stop-Service -Name "ServiceName"
net start ServiceName
net stop ServiceName

# Service details
sc qc ServiceName

# Find service executable path
Get-WmiObject win32_service | Select Name, PathName | Where-Object { $_.PathName -like "*suspicious*" }

PowerShell for Security

# Get running processes with network connections
Get-NetTCPConnection | Where-Object { $_.State -eq "Established" } |
  Select LocalAddress, LocalPort, RemoteAddress, RemotePort,
         @{Name="Process";Expression={(Get-Process -Id $_.OwningProcess).ProcessName}}

# Find recently modified files
Get-ChildItem -Path C:\ -Recurse -File |
  Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-1) }

# Check startup programs
Get-CimInstance Win32_StartupCommand | Select Name, Command, Location

# Get logged-in users
query user
Get-WmiObject Win32_LoggedOnUser

# Network shares
net share
Get-SmbShare

Process Monitor (Sysinternals)

Process Monitor is useful for understanding what processes are doing in real time: file access, registry changes, and network activity.

Download: Sysinternals Process Monitor

Key Filters for Security:
- Operation is WriteFile
- Path contains Run
- Process Name is powershell.exe or cmd.exe
- Event Class is Network

6. Linux Internals Deep Dive

Linux powers a large share of servers, cloud infrastructure, and security tools. Learning its internals gives you practical visibility into real systems.

File System Hierarchy

Directory Purpose Security Relevance
/etc System configuration User accounts, services, cron jobs
/var Variable data (logs, mail, spool) Logs for forensics
/home User home directories User data, ~/.ssh keys, history files
/tmp Temporary files Malware staging area, world-writable
/proc Virtual filesystem (process info) Live process analysis
/root Root user's home High-value target

Special Permission Bits

Bit Numeric Effect Security Impact
SUID 4000 Execute as file owner Privilege escalation if misconfigured
SGID 2000 Execute as group owner Similar risk, check group privileges
Sticky 1000 Only owner can delete files Important for /tmp 
# Find SUID binaries (common privilege escalation target)
find / -perm -4000 -type f 2>/dev/null

# Find SGID binaries
find / -perm -2000 -type f 2>/dev/null

# Find world-writable files
find / -perm -o+w -type f 2>/dev/null

# Find files with no owner
find / -nouser -type f 2>/dev/null

systemd: The Init System

# List all services
systemctl list-units --type=service

# Service status
systemctl status nginx

# Start/Stop/Restart
systemctl start nginx
systemctl stop nginx
systemctl restart nginx

# Enable at boot
systemctl enable nginx

# View service configuration
systemctl cat nginx

# View logs for service
journalctl -u nginx -f

7. macOS Internals Deep Dive

macOS is Unix-based (Darwin kernel = BSD + Mach). Many Linux commands work, but there are unique aspects.

Darwin/XNU Kernel

macOS uses the XNU kernel (X is Not Unix), a hybrid of:

  • Mach, a microkernel handling low-level tasks such as IPC and memory.
  • BSD, a Unix layer providing POSIX compatibility, file systems, and networking.

launchd: The macOS Init System

Unlike Linux's systemd, macOS uses launchd for service management.

Location Purpose Runs As
~/Library/LaunchAgents/ Current user agents User
/Library/LaunchAgents/ All users agents User
/Library/LaunchDaemons/ System daemons Root
/System/Library/LaunchDaemons/ Apple system daemons Root 
# List launch services
launchctl list

# Load/Unload a service
launchctl load /Library/LaunchAgents/com.example.plist
launchctl unload /Library/LaunchAgents/com.example.plist

# Start/Stop
launchctl start com.example.service
launchctl stop com.example.service

# Check for suspicious items
ls -la ~/Library/LaunchAgents/
ls -la /Library/LaunchAgents/
ls -la /Library/LaunchDaemons/

macOS Security Features

Feature What It Does Bypass Implications
SIP (System Integrity Protection) Protects system files from modification, even by root Disabling requires recovery mode boot
Gatekeeper Blocks unsigned/untrusted apps Check app notarization status
TCC (Transparency, Consent, Control) Controls app access to camera, mic, files TCC.db manipulation is common malware target
XProtect Built-in malware signatures Basic AV, signature-based only 
# Check SIP status
csrutil status

# Gatekeeper status
spctl --status

# List TCC permissions
# Database at ~/Library/Application Support/com.apple.TCC/TCC.db

# Check code signing
codesign -dv --verbose=4 /path/to/app

# Verify notarization
spctl -a -v /path/to/app

Useful Security Commands

# List all users
dscl . -list /Users

# Get user details
dscl . -read /Users/username

# Check sudo access
sudo -l

# Find recently modified files
find / -mtime -1 -type f 2>/dev/null

# Network connections

# Running processes with network
