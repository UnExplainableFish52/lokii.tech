1. What is Nmap? (Theory & Foundation)

Nmap (Network Mapper) is a free and open-source network discovery and security auditing tool. Created by Gordon "Fyodor" Lyon in 1997, it has become the industry standard for network exploration.

Why Nmap is Essential:
  • Network Discovery: Find live hosts, open ports, and services
  • Security Auditing: Identify vulnerabilities before attackers do
  • Inventory Management: Map your entire network infrastructure
  • Compliance: Meet PCI-DSS, HIPAA, and other regulatory requirements

👥 Who Uses Nmap?

  • Penetration Testers: Reconnaissance phase of ethical hacking
  • System Administrators: Network inventory and troubleshooting
  • Security Engineers: Vulnerability assessment and compliance
  • SOC Analysts: Incident response and threat hunting
  • Network Engineers: Service monitoring and configuration verification
  • Red Team Operators: Attack surface mapping

🔑 Core Concepts to Understand

What is a Port?

A port is a virtual endpoint for network communication. Think of it like apartment numbers in a building — the IP address is the building, and ports are individual apartments where different services live.

  • Port Range: 0-65535 (total 65,536 ports)
  • Well-Known Ports: 0-1023 (reserved for common services)
  • Registered Ports: 1024-49151
  • Dynamic/Private Ports: 49152-65535

Port States in Nmap

State Meaning
open Application actively accepting connections
closed Port accessible but no application listening
filtered Firewall/filter blocking; Nmap can't determine state
unfiltered Port accessible but open/closed undetermined
open|filtered Can't determine if open or filtered
closed|filtered Can't determine if closed or filtered

3. Basic Syntax & Your First Scan

General Syntax

nmap [Scan Type] [Options] {target specification}

Target Specification

Format Example Description
Single IP nmap 192.168.1.1 Scan one host
Multiple IPs nmap 192.168.1.1 192.168.1.5 Scan specific hosts
Range nmap 192.168.1.1-100 Scan IP range
CIDR nmap 192.168.1.0/24 Scan entire subnet (256 hosts)
Hostname nmap scanme.nmap.org Scan by hostname
From File nmap -iL targets.txt Read targets from file
Exclude nmap 192.168.1.0/24 --exclude 192.168.1.1 Exclude specific hosts

Your First Scan — Try It!

ℹ️ Legal Notice

Always get written permission before scanning networks you don't own. Unauthorized scanning is illegal in most jurisdictions. Use scanme.nmap.org for practice — it's specifically set up for testing!

# Basic scan (scans 1000 most common ports)
nmap scanme.nmap.org

# Scan specific ports
nmap -p 22,80,443 scanme.nmap.org

# Scan port range
nmap -p 1-1000 scanme.nmap.org

# Scan ALL ports (takes longer)
nmap -p- scanme.nmap.org

# Fast scan (top 100 ports)
nmap -F scanme.nmap.org

4. Host Discovery Techniques

Before scanning ports, Nmap needs to know which hosts are alive. This is called host discovery or "ping scanning".

Host Discovery Flags

Flag Technique Best For
-sn Ping Scan (no port scan) Quick network sweep
-Pn Skip host discovery Hosts that block ping
-PS TCP SYN ping Firewall evasion
-PA TCP ACK ping Stateful firewall evasion
-PU UDP ping Hosts filtering TCP
-PE ICMP Echo ping Local networks
-PP ICMP Timestamp ping When echo blocked
-PM ICMP Netmask ping Alternative ICMP
-PR ARP ping (local only) Same subnet - most reliable

Practical Examples

# Find all live hosts on your network (no port scan)
nmap -sn 192.168.1.0/24

# Scan host even if it doesn't respond to ping
nmap -Pn 192.168.1.50

# Use TCP SYN ping on port 80 and 443
nmap -PS80,443 192.168.1.0/24

# Use ARP discovery (best for local network)
nmap -PR 192.168.1.0/24

# Combine multiple discovery methods
nmap -PE -PS22,80,443 -PA80 192.168.1.0/24

🎯 Real Scenario: Network Inventory

Task: You're a sysadmin and need to find all devices on the 10.0.0.0/24 network.

# Quick discovery scan
nmap -sn 10.0.0.0/24 -oG - | grep "Up" | awk '{print $2}'

# With hostnames
nmap -sn 10.0.0.0/24

5. Port Scanning Types

Different scan types use different TCP flags and techniques. Choosing the right scan depends on your goal: stealth, speed, or accuracy.

TCP Scans

Flag Scan Type How It Works Stealth
-sS SYN Scan (Half-open) Sends SYN, waits for SYN/ACK, sends RST ⭐⭐⭐
-sT Connect Scan Full TCP connection (3-way handshake) ⭐
-sA ACK Scan Sends ACK to detect firewall rules ⭐⭐
-sW Window Scan Like ACK but examines window field ⭐⭐
-sM Maimon Scan FIN/ACK probe ⭐⭐

Stealth Scans (NULL, FIN, Xmas)

Flag Scan Type Flags Sent
-sN NULL Scan No flags set
-sF FIN Scan Only FIN flag
-sX Xmas Scan FIN + PSH + URG (like a Christmas tree)

ℹ️ How Stealth Scans Work

According to RFC 793, when a closed port receives packets without SYN, RST, or ACK, it should respond with RST. An open port will simply drop the packet silently. This allows detection without completing connections — but doesn't work on Windows (which ignores the RFC).

UDP Scan

# UDP scan (slower because no handshake)
nmap -sU 192.168.1.1

# Scan specific UDP ports
nmap -sU -p 53,67,68,161,500 192.168.1.1

# Combined TCP and UDP
nmap -sS -sU -p T:22,80,443,U:53,161 192.168.1.1

Practical Examples

# Default SYN scan (requires root/admin)
sudo nmap -sS 192.168.1.1

# Connect scan (no root needed)
nmap -sT 192.168.1.1

# Xmas scan for firewall testing
sudo nmap -sX 192.168.1.1

# ACK scan to map firewall rules
sudo nmap -sA 192.168.1.1

6. Service & Version Detection

Finding open ports is just the beginning. Version detection tells you exactly what's running — crucial for vulnerability assessment.

Version Detection Flags

Flag Purpose
-sV Enable version detection
--version-intensity [0-9] How hard to try (0=light, 9=all probes)
--version-light Quick version scan (intensity 2)
--version-all Try all probes (intensity 9) 
# Basic version detection
nmap -sV 192.168.1.1

# Aggressive version detection
nmap -sV --version-all 192.168.1.1

# Combined with service scripts
nmap -sV -sC 192.168.1.1

🎯 Real Scenario: Vulnerability Assessment

Task: Find outdated services on a web server.

# Detailed version scan on common ports
nmap -sV --version-all -p 21,22,80,443,3306,8080 webserver.local

# Output shows:
# PORT     STATE SERVICE  VERSION
# 22/tcp   open  ssh      OpenSSH 7.2p2 Ubuntu
# 80/tcp   open  http     Apache httpd 2.4.18
# 443/tcp  open  ssl/http Apache httpd 2.4.18
# 3306/tcp open  mysql    MySQL 5.5.62

Now you can check these versions against CVE databases!

7. OS Detection & Fingerprinting

Nmap can identify operating systems by analyzing how targets respond to specially crafted probes.

OS Detection Flags

Flag Purpose
-O Enable OS detection
--osscan-limit Skip OS detection for hosts without open+closed ports
--osscan-guess Guess OS more aggressively
--max-os-tries Max attempts (default 5) 
# Basic OS detection
sudo nmap -O 192.168.1.1

# Aggressive OS guessing
sudo nmap -O --osscan-guess 192.168.1.1

# Combined with version detection (common combo)
sudo nmap -O -sV 192.168.1.1

💡 The "Aggressive" Shortcut: -A

The -A flag enables: OS detection (-O) + Version detection (-sV) + Script scanning (-sC) + Traceroute (--traceroute). Perfect for comprehensive reconnaissance!

sudo nmap -A 192.168.1.1

8. Nmap Scripting Engine (NSE)

NSE is what makes Nmap truly powerful. It's a Lua-based scripting engine with 600+ scripts for vulnerability detection, exploitation, and more.

Script Categories

Category Description
auth Authentication and credential testing
broadcast Network broadcast discovery
brute Brute force attacks
default Safe, useful scripts (-sC)
discovery Service discovery
dos Denial of Service (use carefully!)
exploit Active exploitation
fuzzer Fuzzing tests
intrusive Risky scripts that might crash services
malware Malware detection
safe Won't crash services
version Version detection enhancement
vuln Vulnerability detection

Using NSE Scripts

# Run default scripts
nmap -sC 192.168.1.1

# Run specific script
nmap --script=http-title 192.168.1.1

# Run multiple scripts
nmap --script=http-title,http-headers 192.168.1.1

# Run category of scripts
nmap --script=vuln 192.168.1.1

# Run all safe scripts
nmap --script=safe 192.168.1.1

# Combine categories
nmap --script="vuln and safe" 192.168.1.1

# Exclude specific scripts
nmap --script="default and not intrusive" 192.168.1.1

Essential Security Scripts

# Check for vulnerabilities
nmap --script vuln 192.168.1.1

# SSL/TLS vulnerability check
nmap --script ssl-heartbleed,ssl-poodle,ssl-ccs-injection -p 443 192.168.1.1

# SMB vulnerabilities (EternalBlue etc.)
nmap --script smb-vuln* -p 445 192.168.1.1

# HTTP security headers
nmap --script http-security-headers -p 80,443 192.168.1.1

# DNS zone transfer
nmap --script dns-zone-transfer -p 53 ns.target.com

# FTP anonymous login
nmap --script ftp-anon -p 21 192.168.1.1

# SSH auth methods
nmap --script ssh-auth-methods -p 22 192.168.1.1

⚠️ Warning: Intrusive Scripts

Scripts in the intrusive, dos, exploit, and brute categories can crash services or trigger security alerts. Only use with explicit permission!

9. Timing & Performance

Balance between speed and stealth. Faster scans are noisier; slower scans evade detection.

Timing Templates

Flag Name Use Case
-T0 Paranoid IDS evasion (very slow)
-T1 Sneaky IDS evasion
-T2 Polite Reduce bandwidth/load
-T3 Normal Default
-T4 Aggressive Fast scan on reliable network
-T5 Insane Very fast, may miss ports

Fine-Tuned Timing Options

# Set max outstanding probes
nmap --min-parallelism 100 192.168.1.0/24

# Set timeout values
nmap --host-timeout 30m 192.168.1.0/24

# Set probe rate
nmap --min-rate 1000 192.168.1.0/24
nmap --max-rate 500 192.168.1.0/24

# Set scan delay (for IDS evasion)
nmap --scan-delay 1s 192.168.1.1

10. Output Formats

Save your scans for documentation, parsing, and reporting.

Output Options

Flag Format Best For
-oN file.txt Normal Human-readable
-oG file.gnmap Grepable grep/awk parsing
-oX file.xml XML Tool import (Metasploit, etc.)
-oS file.txt Script Kiddie Just for fun (leet speak)
-oA basename All formats Creates .nmap, .gnmap, .xml 
# Save in all formats
nmap -sV -oA myscan 192.168.1.0/24

# Append to existing file
nmap --append-output -oN results.txt 192.168.1.1

# Verbose output to screen + file
nmap -v -sV -oN scan.txt 192.168.1.1

11. Firewall Evasion & Stealth

Evasion Techniques

Flag Technique
-f Fragment packets
--mtu [size] Set specific MTU
-D decoy1,decoy2,ME Decoy scan (hide among fake IPs)
-S [IP] Spoof source IP
-e [interface] Use specific interface
--source-port [port] Use specific source port
--data-length [len] Append random data to packets
--randomize-hosts Randomize target order
--badsum Send packets with bad checksums 
# Fragment packets to bypass simple firewalls
sudo nmap -f 192.168.1.1

# Decoy scan - your IP hidden among decoys
sudo nmap -D 10.0.0.1,10.0.0.2,ME 192.168.1.1

# Randomize host order in large scans
nmap --randomize-hosts 192.168.1.0/24

# Combine multiple evasion techniques
sudo nmap -sS -T2 -f --source-port 53 --randomize-hosts 192.168.1.0/24

12. Real-World Scenarios

🎯 Scenario 1: Initial Reconnaissance

Task: As a pentester, do initial recon on a target network.

# Step 1: Find live hosts
nmap -sn 10.10.10.0/24 -oG hosts.gnmap

# Step 2: Quick port scan on live hosts
nmap -iL live_hosts.txt -F -oA quick_scan

# Step 3: Detailed scan on interesting hosts
nmap -sV -sC -O -p- -oA detailed_scan 10.10.10.50

🎯 Scenario 2: Web Server Assessment

Task: Assess security of a web server.

# Full web scan
nmap -sV -sC -p 80,443,8080,8443 \
  --script http-enum,http-headers,http-methods,http-security-headers \
  -oA web_scan target.com

🎯 Scenario 3: SMB Vulnerability Check

Task: Check for SMB vulnerabilities (WannaCry, EternalBlue).

# SMB vulnerability scan
nmap -p 445 --script smb-vuln-ms17-010,smb-vuln-ms08-067 192.168.1.0/24

🎯 Scenario 4: Network Inventory for Sysadmin

Task: Create inventory of all devices and services.

# Comprehensive network inventory
nmap -sV -O --top-ports 1000 -oX inventory.xml 192.168.1.0/24

# Parse and view results
xsltproc inventory.xml -o inventory.html

14. Knowledge Quiz

Test your Nmap knowledge! Try to answer before revealing the solution.

🧠 Quiz 1: Basic Scanning

How would you scan the top 100 ports on 192.168.1.50?

Click to reveal answer 
nmap -F 192.168.1.50

The -F flag performs a "Fast" scan of the top 100 most common ports.

🧠 Quiz 2: Stealth Scanning

You need to scan a host while avoiding detection. What scan type and timing would you use?

Click to reveal answer 
sudo nmap -sS -T2 192.168.1.50

SYN scan (-sS) is stealthier than connect scan, and -T2 (Polite) slows down to reduce detection risk.

🧠 Quiz 3: Full Enumeration

You found a web server and want to: detect OS, find service versions, run default scripts, and save in all formats as "webserver_scan".

Click to reveal answer 
sudo nmap -A -oA webserver_scan target.com

Or more explicitly:

sudo nmap -O -sV -sC --traceroute -oA webserver_scan target.com

🧠 Quiz 4: Vulnerability Scanning

How do you check if a Windows machine is vulnerable to EternalBlue?

Click to reveal answer 
nmap -p 445 --script smb-vuln-ms17-010 192.168.1.50

This runs the specific NSE script that checks for MS17-010 (EternalBlue) vulnerability.

🧠 Quiz 5: Network Discovery

Find all live hosts on 10.0.0.0/24 without port scanning, saving results to live_hosts.txt.

Click to reveal answer 
nmap -sn 10.0.0.0/24 -oG live_hosts.txt

-sn does ping sweep only (no port scan), and -oG saves in grepable format for easy parsing.

🧠 Quiz 6: Firewall Evasion

A firewall is blocking your scans. Try scanning with fragmented packets, using DNS source port, with random host order.

Click to reveal answer 
sudo nmap -sS -f --source-port 53 --randomize-hosts 192.168.1.0/24

Combines fragmentation, DNS port (often allowed through firewalls), and randomization to evade detection.

🧠 Quiz 7: Service Identification

Port 8080 is open. Get detailed version info with maximum intensity.

Click to reveal answer 
nmap -sV --version-all -p 8080 192.168.1.50

Or use --version-intensity 9 for the same effect.

🧠 Quiz 8: UDP Services

Check for SNMP (161) and DNS (53) UDP services on a network segment.

Click to reveal answer 
sudo nmap -sU -p 53,161 192.168.1.0/24

UDP scans require root/admin privileges and are slower than TCP scans.
