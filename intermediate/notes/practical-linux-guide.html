Intermediate 2.2 Field Guide

Practical Linux Guide

A linear Linux reference for turning the full course into quick checks, useful actions, and field-ready habits.

This page is an orientation before doing real work with Linux. It assumes you have already completed the full Linux course and now need a practical, repeatable way to inspect systems, troubleshoot issues, and collect useful evidence.

How to Use This Guide

This guide follows a strict format: to do a practical task, use the matching command, then adjust the flags, values, paths, users, services, or targets to match the job in front of you.

  • Use it after the full Linux course, not as a replacement for the course.
  • Run commands only on systems you own, administer, or have permission to inspect.
  • Prefer read-only checks first. Use destructive or account-changing commands only when you understand the impact.
  • Keep notes when investigating: command, timestamp, system, output summary, and what you checked next.
How to read placeholders and flags
  • file_name, folder_name, username, service_name, interface_name, and host are placeholders. Replace them with the real file, folder, account, service, interface, or remote system.
  • Flags change command behavior. For example, -h often means human-readable, -a often means all, -r often means recursive, and -n often controls a number. Always confirm with command --help when a command is new to you.
  • Numbers are usually adjustable. Change -c 4 to -c 10 for more ping packets, -n 50 to -n 200 for more log lines, or +100M to +1G for larger file searches.
  • Paths control scope. Start with a narrow path such as your home directory or a lab folder before scanning all of /.

Page rule: Every entry should stay practical: one goal, one command, and one short explanation. Add commands only when they help real Linux usage, troubleshooting, security checking, system administration, or investigation.

Phase 1: Basic Recon

Goal: quickly understand what system you are working with.

Flags and values to adjust in basic recon
  • uname -a: -a prints all common system fields. Use uname -r for only the kernel release, uname -m for CPU architecture, and uname -n for the network node name.
  • hostname: use plain hostname for the system name, hostname -I for assigned IP addresses, and hostnamectl on systemd systems for the static hostname and OS summary.
  • id: use plain id for your own identity, id username for another user, id -u for only the UID, and id -nG username for group names only.
  • grep "/bin/bash" /etc/passwd: change /bin/bash to another shell such as /bin/zsh, or use getent passwd when accounts may come from LDAP, AD, or another identity source.
  • curl icanhazip.com: add -4 or -6 to force IPv4 or IPv6, and use -s for quiet script-friendly output.
  • ip a: use ip -br a for a compact view, ip a show interface_name for one interface, and ip link when you only need link state.

To check kernel and system information

uname -a

Shows the kernel version, architecture, hostname, and system build details.

To check the current hostname

hostname

Shows the system name on the network.

To check who you are logged in as

whoami

Shows the current username.

To check your user ID and groups

id

Shows your UID, GID, and group memberships.

To check your current directory

pwd

Prints the full path of your current working directory.

How to adjust it
  • pwd has no normal flags needed for daily work. Use it before copying, deleting, or moving files so you know where the command will run.
  • Use it in scripts when output paths depend on the current directory.

To list files clearly

ls -lah

Lists files, hidden entries, permissions, owners, sizes, and modification times in a readable format.

Flags and variants
  • -l uses long format with permissions, owner, group, size, and time.
  • -a includes hidden files that start with a dot.
  • -h makes sizes readable, such as 4K, 20M, or 1G.
  • Use ls -ltr to sort by time with newest entries at the bottom, or ls -lah folder_name to inspect a specific folder.

To move into another directory

cd /path/to/folder

Changes your current working directory to the selected path.

Values and variants
  • Replace /path/to/folder with an absolute path such as /var/log or a relative path such as ../notes.
  • Use cd to return to your home directory, cd - to jump back to the previous directory, and cd .. to move one level up.
  • Run pwd after changing directories if the next command will modify files.

To view users on the system

cat /etc/passwd

Lists local user accounts stored on the system.

To view users from the active identity source

getent passwd

Shows user accounts using the system name service configuration, not only the local password file.

Values and variants
  • Use getent passwd username to check one account.
  • Prefer getent over cat /etc/passwd when the system may use LDAP, Active Directory, NIS, or another external identity source.

To filter normal login users

grep "/bin/bash" /etc/passwd

Shows users that likely have an interactive shell.

To view general system information

fastfetch

Shows a quick summary of OS, kernel, shell, CPU, memory, and desktop environment.

To view shell environment variables

env | sort

Shows environment variables in alphabetical order, which helps when checking shell, PATH, proxy, or application settings.

Values and variants
  • Use printenv PATH to check one variable.
  • Use env | grep -i proxy to find proxy-related settings.
  • Do not paste full environment output publicly. It may contain tokens, paths, usernames, or internal hostnames.

To check public IP address

curl icanhazip.com

Shows the public IP address seen from the internet.

To check local IP addresses and interfaces

ip a

Shows local IP addresses, network interfaces, and connection state.

Phase 2: System Health

Goal: check whether the system is healthy, overloaded, or running out of resources.

Flags and values to adjust in system health checks
  • top: press P to sort by CPU, M to sort by memory, k to send a signal, and q to quit. Use top -o %MEM when you want memory-heavy processes first.
  • free -h: -h makes values readable. Use free -m for MiB, free -g for GiB, and focus on the available column for practical capacity.
  • df -h: -h makes disk sizes readable. Add a path such as df -h /var to check the filesystem holding that path.
  • du -sh folder_name: -s summarizes instead of listing every child, and -h makes the result readable. Replace folder_name with the folder you are measuring.
  • uptime: compare the load averages to CPU count from nproc. A load near or above CPU count for a long time deserves investigation.

To check live resource usage

htop

Shows live CPU, RAM, process, and resource usage in an interactive view.

How to use it
  • Use function keys or the bottom menu to search, filter, sort, and inspect processes.
  • Press F6 to change sort column, F9 to send a signal, and q to quit.
  • Use this for live triage. Save evidence separately with commands such as ps aux or screenshots if needed.

To check live resource usage without htop

top

Shows live processes and resource usage using a default Linux tool.

To check memory usage

free -h

Shows used, free, and available RAM in human-readable format.

To check disk usage

df -h

Shows mounted disks and available storage.

Flags and variants
  • -h makes sizes readable.
  • Use df -h /path to check the filesystem that contains a specific path.
  • Use df -i when a disk has free space but still cannot create files. That checks inode usage.

To check folder size

du -sh folder_name

Shows the total size of a specific folder.

Flags and variants
  • -s gives one total instead of every nested folder.
  • -h prints readable units.
  • Use du -h --max-depth=1 folder_name to see which immediate child folder is using space.
  • Use sudo du -sh /var/log only when normal permissions hide important folders.

To check system uptime and load

uptime

Shows how long the system has been running and its load average.

To check CPU count

nproc

Shows how many processing units Linux sees.

How to use the value
  • Compare this number with uptime load averages. A 4-core system can tolerate a different load than a 1-core system.
  • Use lscpu when you need more detail about sockets, cores, threads, architecture, and virtualization.

To check block devices and mount layout

lsblk -f

Shows disks, partitions, filesystems, labels, UUIDs, and mount points.

Flags and variants
  • -f includes filesystem details.
  • Use plain lsblk for a simpler tree.
  • Use this before disk, partition, or mount work so you do not confuse devices.

Phase 3: Process Management

Goal: understand what is running and stop processes safely when needed.

Flags and values to adjust in process checks
  • ps aux: a shows processes for all users, u uses a user-oriented format, and x includes processes without a terminal.
  • pgrep -a process_name: -a prints the full command line. Add -u username to search only one user's processes, or -f to match the full command line.
  • pstree -p: -p shows PIDs. Use pstree -ap to include command arguments.
  • kill PID: plain kill sends SIGTERM. Use kill -15 PID for the same signal explicitly, and reserve kill -9 PID for stuck processes.
  • pkill process_name: match carefully. Use pgrep -a process_name first so you can see what will be affected.

To view all running processes

ps aux

Shows all running processes with their users, CPU usage, memory usage, and PID.

Useful variants
  • ps aux --sort=-%cpu | head shows high CPU processes near the top.
  • ps aux --sort=-%mem | head shows high memory processes near the top.
  • ps -u username shows processes owned by one user.

To find a process by name

pgrep -a process_name

Finds matching processes and shows their PIDs with command details.

To view processes as a tree

pstree -p

Shows parent-child relationships between processes with PIDs.

To stop a process safely

kill PID

Sends SIGTERM, asking the process to stop cleanly.

Safety and variants
  • Replace PID with the process ID from ps, pgrep, top, or htop.
  • Use kill -15 PID when you want to be explicit about SIGTERM.
  • Wait a few seconds and verify with pgrep -a process_name before escalating.

To force-stop a stuck process

kill -9 PID

Sends SIGKILL, useful only when a process refuses to stop normally.

Safety and variants
  • -9 sends SIGKILL, which the process cannot cleanly handle.
  • Use this only after kill PID or kill -15 PID fails.
  • Avoid this on databases, package managers, backups, or write-heavy processes unless you understand the risk of corruption.

To kill a process by name

pkill process_name

Stops processes matching the given name.

Flags and safer workflow
  • Run pgrep -a process_name first to preview matches.
  • Use pkill -u username process_name to limit matching to one user.
  • Use pkill -f pattern only when you need to match the full command line. This can catch more than expected.

To inspect open files for a process

lsof -p PID

Shows files, sockets, and resources opened by a specific process.

Values and variants
  • Replace PID with the process ID you are investigating.
  • Use lsof -i to focus on network sockets.
  • Use this when a process will not release a file, port, or mounted filesystem.

Phase 4: Networking

Goal: understand IPs, routes, ports, DNS, connectivity, and packet movement.

Flags and values to adjust in networking commands
  • ip a: use ip -br a for a compact view, ip a show interface_name for one interface, and ip link set interface_name up only when you intentionally change interface state.
  • ip r: use ip r get 8.8.8.8 to see the route Linux would use for a specific destination.
  • ss -tulpen: -t TCP, -u UDP, -l listening sockets, -p process info, -e extended info, and -n numeric output.
  • ping -c 4 8.8.8.8: change 4 to the number of packets you want. Change the target to your gateway, DNS server, or domain depending on what layer you are testing.
  • dig example.com: change the domain, query type, or DNS server. For example, dig A example.com, dig MX example.com, or dig @1.1.1.1 example.com.
  • tcpdump: always set the interface and capture filter deliberately. Captures can include sensitive traffic.

To check local IP addresses

ip a

Shows local IPs, interfaces, and link status.

Flags and variants
  • Use ip -br a for a compact interface summary.
  • Use ip a show interface_name to inspect one interface, such as eth0, wlan0, or ens33.
  • Use ip link when you only need link state, MAC address, and interface flags.

To check network routes

ip r

Shows the default gateway and routing table.

Values and variants
  • Look for the default via line to identify the default gateway.
  • Use ip r get target_ip to see which interface and gateway Linux will use for a target.
  • Use this before blaming DNS or a service. Bad routes can make everything above them look broken.

To check listening ports

ss -tulpen

Shows TCP/UDP listening ports, related processes, and users.

Flags and variants
  • -t shows TCP sockets and -u shows UDP sockets.
  • -l limits output to listening sockets.
  • -p shows process details when permissions allow it.
  • -n avoids name resolution so output is faster and shows numeric ports.
  • Use sudo ss -tulpen if process names are hidden.

To test internet connectivity

ping -c 4 8.8.8.8

Tests whether the system can reach the internet by IP.

Flags and target choices
  • -c 4 sends 4 packets. Increase it for a longer check or lower it for a quick test.
  • Ping your gateway first when testing local network reachability.
  • Ping a public IP such as 8.8.8.8 to test routing without depending on DNS.
  • Ping a domain such as example.com only when you also want DNS involved.

To test DNS resolution

dig example.com

Checks whether domain names are resolving correctly.

Values and variants
  • Replace example.com with the domain you are testing.
  • Use dig A domain for IPv4 records and dig AAAA domain for IPv6 records.
  • Use dig @1.1.1.1 domain to query a specific DNS server.
  • Use dig +short domain when you only need the answer.

To check public IP

curl icanhazip.com

Shows the public IP address of the system.

To capture packets on an interface

sudo tcpdump -i interface_name -w capture.pcap

Captures network traffic and saves it into a packet capture file.

Flags and safe capture patterns
  • -i interface_name chooses the interface. Replace it with eth0, wlan0, ens33, or the interface from ip -br a.
  • -w capture.pcap writes packets to a file for Wireshark or later analysis.
  • Add -c 100 to stop after 100 packets.
  • Add a filter such as host 192.168.1.10, port 53, or tcp to reduce noise.
  • Packet captures can contain credentials or private data. Store and share them carefully.

To trace the path to a destination

tracepath example.com

Shows the network hops toward a destination without requiring root on many systems.

Values and variants
  • Replace example.com with a domain or IP you are troubleshooting.
  • Use this when ping works inconsistently or you need to know where a path may be failing.
  • If tracepath is unavailable, try traceroute example.com if installed.

To connect to another system over SSH

ssh user@host

Starts a secure remote shell session to another system.

Values and variants
  • Replace user with the remote username and host with a hostname or IP address.
  • Use ssh -p 2222 user@host when SSH is running on a non-default port.
  • Use ssh -i key_file user@host when authenticating with a specific private key.
  • Do not connect to systems without permission.

To transfer a file securely to another system

scp capture.pcap user@host:/path/

Copies a file securely over SSH.

Values and variants
  • Replace capture.pcap with the local file you want to send.
  • Replace user@host:/path/ with the remote account, system, and destination folder.
  • Use scp -P 2222 file user@host:/path/ for a non-default SSH port. In scp, the port flag is uppercase -P.
  • Use scp -r folder user@host:/path/ only when intentionally copying a whole folder recursively.

Phase 5: Users and Privileges

Goal: understand accounts, groups, passwords, sudo access, and user control.

Flags and values to adjust for users and privileges
  • id username and groups username: replace username with the account you are checking. Use plain id or groups for your current account.
  • sudo -l: lists allowed sudo commands for your current user. Use sudo -l -U username only if you have permission to inspect another user's sudo rules.
  • passwd, usermod, and userdel change accounts. Confirm the account name before running them.
  • usermod -aG group_name username: -a appends and -G sets supplementary groups. Do not omit -a when adding a group, or you may replace existing memberships.
  • userdel -r username removes the account and home directory. Back up required files first.

To check your current user

whoami

Shows the username of the current session.

To check a user's ID and groups

id username

Shows the UID, GID, and groups for a specific user.

To check a user's groups

groups username

Shows which groups the user belongs to.

To check your sudo permissions

sudo -l

Shows what commands your user can run with sudo.

How to read it
  • Look for commands listed after the host and run-as section. Those are what the user can run with sudo.
  • (ALL : ALL) ALL means broad sudo access. Treat that as high privilege.
  • NOPASSWD means sudo may not ask for a password for listed commands.

To change a user password

sudo passwd username

Changes the password for a user account.

Values and caution
  • Replace username with the exact account name.
  • Use passwd without sudo to change your own password.
  • Changing passwords can interrupt active users or service accounts. Confirm intent first.

To lock a user account

sudo usermod -L username

Locks the user account from password login.

Flags and caution
  • -L locks the password by modifying the password hash state.
  • This blocks password login, but it may not disable all access methods such as existing sessions or SSH keys.
  • Use sudo passwd -S username to inspect password status on many Linux systems.

To unlock a user account

sudo usermod -U username

Unlocks a previously locked user account.

Flags and caution
  • -U unlocks the password state.
  • Confirm the account should be restored before unlocking it.
  • If the account was locked for incident response, document who approved the unlock.

To add a user to a group

sudo usermod -aG group_name username

Adds a user to a group without removing existing group memberships.

Flags and values
  • -a appends new groups instead of replacing the user's existing supplementary groups.
  • -G group_name sets the supplementary group list. Use comma-separated groups for multiple additions.
  • Replace group_name and username carefully. Adding a user to sudo, wheel, docker, or similar groups can grant serious privilege.
  • The user may need to log out and back in before new group membership applies.

To delete a user

sudo userdel username

Deletes a user account but keeps the home directory.

Safety notes
  • Replace username with the exact account name.
  • Check id username, last username, and running processes before deletion.
  • This keeps the home directory, which is safer when you may need to recover files or evidence.

To delete a user with home directory

sudo userdel -r username

Deletes the user account and its home directory.

Flags and caution
  • -r removes the user's home directory and mail spool.
  • Back up required files before running this.
  • Prefer plain userdel username when you are not sure whether the home directory contains evidence or useful data.

To create a new user account

sudo useradd -m -s /bin/bash username

Creates a user with a home directory and sets the login shell.

Flags and values
  • -m creates the home directory.
  • -s /bin/bash sets the login shell. Change it to another approved shell when needed.
  • Set the password separately with sudo passwd username.
  • Use this only when account creation is part of an approved admin task.

Phase 6: Files, Metadata, and Changes

Goal: inspect files, permissions, ownership, size, and recent changes.

Flags and values to adjust for file work
  • stat file_name: replace file_name with any file or folder. Use it when timestamps, ownership, permissions, or inode details matter.
  • ls -lah file_name: -l long format, -a hidden files, and -h readable sizes. Add a folder path to inspect that folder.
  • find /path: replace /path with the smallest safe search scope. Searching / can be slow and noisy.
  • -mtime -1: files modified within the last 24 hours. Change -1 to -7 for seven days or +30 for older than 30 days.
  • -size +100M: files larger than 100 MiB. Change 100M to 1G, 500M, or another threshold.
  • chmod and chown change access. Use them only after checking current permissions and ownership.

To view file metadata

stat file_name

Shows file size, permissions, owner, access time, modify time, and change time.

Values and variants
  • Replace file_name with a file or folder path.
  • Use stat -c "%A %U %G %s %n" file_name for a compact permissions, owner, group, size, and name view on GNU systems.
  • Use this when checking evidence timing or permission changes.

To view file permissions clearly

ls -lah file_name

Shows permissions, owner, group, size, and modification time.

Flags and variants
  • -l shows long format, including permission bits.
  • -a includes hidden files.
  • -h prints readable sizes.
  • Use ls -ld folder_name to inspect the folder itself instead of its contents.

To copy files while preserving metadata

cp -av source_path destination_path

Copies files or folders while preserving useful metadata and showing what is copied.

Flags and values
  • -a archive mode preserves mode, ownership where possible, timestamps, symlinks, and recursively copies directories.
  • -v prints each copied item.
  • Replace source_path and destination_path carefully. Use a test folder first if you are unsure.
  • Use cp -i source destination when you want a prompt before overwrite.

To move or rename a file safely

mv -i old_name new_name

Moves or renames a file and asks before overwriting an existing destination.

Flags and values
  • -i prompts before overwrite.
  • Use mv file folder/ to move into a folder.
  • Use mv old_name new_name to rename in the same folder.
  • Be careful when moving logs, configs, or evidence files. Keep a copy if rollback matters.

To change file permissions

chmod 640 file_name

Changes who can read, write, or execute a file.

Values and caution
  • 640 means owner can read/write, group can read, others get no access.
  • Use chmod +x script.sh to make a script executable.
  • Use chmod -R only when you intentionally want recursive permission changes. Recursive permission mistakes can break applications or expose data.
  • Check current permissions first with ls -lah file_name.

To change file ownership

sudo chown user:group file_name

Changes the owner and group assigned to a file or folder.

Values and caution
  • Replace user and group with real account and group names.
  • Use sudo chown -R user:group folder_name only when recursive ownership changes are required.
  • Wrong ownership can break services or expose private files. Check with ls -lah before and after.

To find recently modified files

find /path -type f -mtime -1

Finds files modified within the last 24 hours.

Flags and values
  • Replace /path with the folder to search.
  • -type f limits results to files. Use -type d for directories.
  • -mtime -1 means modified less than one day ago. Use -mtime -7 for the last week or -mtime +30 for older than 30 days.
  • Add -ls to show file metadata with results.

To find large files

find /path -type f -size +100M

Finds files larger than 100 MB.

Flags and values
  • -size +100M finds files larger than 100 MiB.
  • Change the threshold to +500M, +1G, or another practical limit.
  • Use -xdev when searching from / but you do not want to cross into other mounted filesystems.

To find hidden files

find /path -name ".*"

Finds hidden files and directories.

Values and variants
  • Replace /path with a narrow folder, such as a user's home directory.
  • Add -type f for hidden files only or -type d for hidden directories only.
  • Hidden does not mean malicious. Treat results as leads, not conclusions.

To find world-writable files

find /path -type f -perm -o+w

Finds files that any user on the system can write to.

Flags and values
  • -perm -o+w matches files where the "others" write bit is set.
  • Replace /path with a focused scope such as /var/www or a project folder.
  • Use find /path -type d -perm -o+w to check world-writable directories.
  • Review context before changing permissions. Some temporary directories are intentionally writable.

To calculate a file hash

sha256sum file_name

Creates a SHA-256 hash for integrity checking or evidence tracking.

Values and variants
  • Replace file_name with the file you want to verify.
  • Use sha256sum file_name > file_name.sha256 to save a hash record.
  • Use sha256sum -c file_name.sha256 to verify later.
  • Hash before and after transfer when evidence integrity matters.

To read a long file safely

less file_name

Opens a file in a pager without editing it.

Keys and variants
  • Press /pattern to search, n for next match, and q to quit.
  • Use less +G file_name to open at the end of a file.
  • Prefer less over opening large logs in an editor.

To view the end of a file

tail -n 50 file_name

Shows the last 50 lines of a file, useful for recent log entries.

Flags and values
  • -n 50 controls how many lines to show. Change 50 to the amount you need.
  • Use tail -f file_name to follow new lines as they are written.
  • Use Ctrl+C to stop following a file.

To view the start of a file

head -n 20 file_name

Shows the first 20 lines of a file, useful for checking headers or file format.

Flags and values
  • -n 20 controls how many lines to show.
  • Use this before parsing unknown files so you understand the structure.

Optional Phase 7: Services and Startup

Goal: check what runs automatically, what is active, and what failed.

Flags and values to adjust for services
  • --type=service limits output to service units. Change the type only when inspecting sockets, timers, mounts, or other unit types.
  • --state=enabled, --state=running, and --failed control which unit state you inspect.
  • service_name should be a real unit such as ssh, nginx, apache2, docker, or cron. Use tab completion or systemctl list-units to confirm the exact name.
  • stop, restart, disable, and enable change system behavior. Check status first and document why you changed it.

To check services enabled at boot

systemctl list-unit-files --type=service --state=enabled

Shows services configured to start automatically with the system.

Flags and variants
  • list-unit-files shows unit file enablement, not necessarily what is running right now.
  • --type=service filters to service units.
  • --state=enabled shows services enabled for boot.
  • Change enabled to disabled to review services that do not start at boot.

To check currently running services

systemctl list-units --type=service --state=running

Shows services currently active on the system.

Flags and variants
  • list-units shows loaded runtime units.
  • --state=running limits output to currently running services.
  • Use systemctl list-units --type=service without the state filter to see more service states.

To check failed services

systemctl --failed

Shows services that failed to start or crashed.

To check one service

systemctl status service_name

Shows whether a service is running, failed, disabled, or enabled.

Values and variants
  • Replace service_name with the real unit name.
  • Use systemctl status service_name --no-pager for output that does not open in a pager.
  • Use systemctl is-active service_name for script-friendly active/inactive checks.
  • Use systemctl is-enabled service_name to check boot enablement.

To stop a service

sudo systemctl stop service_name

Stops a running service until it is started again or the system reboots.

Safety and variants
  • Check systemctl status service_name before stopping it.
  • stop affects the current boot only.
  • Use sudo systemctl start service_name to start it again.
  • Stopping SSH, network, database, or production services can disconnect users or break applications.

To disable a service from boot

sudo systemctl disable service_name

Prevents a service from starting automatically at boot.

Safety and variants
  • disable changes boot behavior but does not necessarily stop the running service.
  • Use sudo systemctl disable --now service_name only when you want to disable and stop it immediately.
  • Use sudo systemctl enable service_name to enable it again at boot.
  • Document the reason before disabling security, logging, networking, or backup services.

To restart or reload a service

sudo systemctl restart service_name

Stops and starts a service, usually to apply configuration changes.

Values and safer choices
  • Use restart when the service must fully stop and start.
  • Use reload instead of restart when the service supports reloading config without dropping active sessions.
  • Run sudo systemctl reload-or-restart service_name when you want reload if supported, restart otherwise.
  • Check status and logs after restarting.

Optional Phase 8: Logs and Investigation

Goal: check what happened recently on the system.

Flags and values to adjust for logs
  • --since accepts practical time windows such as "10 minutes ago", "1 hour ago", "24 hours ago", or "2026-06-30 09:00".
  • journalctl -u service_name filters to one service. Replace service_name with the unit you are investigating.
  • -n 100 controls how many recent log lines to show. Change the number based on how much context you need.
  • -f follows new log entries live. Stop with Ctrl+C.
  • grep patterns are adjustable. Change "Failed password" to the exact phrase you need to find.

To check recent system logs

journalctl --since "1 hour ago"

Shows system logs from the last hour.

Time windows and variants
  • Change "1 hour ago" to "10 minutes ago", "24 hours ago", or a specific timestamp.
  • Use journalctl -n 100 for the last 100 log lines.
  • Use journalctl -f to follow logs live.
  • Add --no-pager when capturing output or using scripts.

To check logs for one service

journalctl -u service_name --since "1 hour ago"

Shows recent logs for a specific service.

Values and variants
  • Replace service_name with a unit such as ssh, nginx, docker, or cron.
  • Change --since to match the incident or troubleshooting window.
  • Use journalctl -u service_name -f to follow one service live.
  • Use journalctl -u service_name -b to show logs from the current boot.

To check recent sudo usage

journalctl _COMM=sudo --since "24 hours ago"

Shows sudo commands used recently.

Filters and values
  • _COMM=sudo filters logs where the command name is sudo.
  • Change "24 hours ago" to your investigation window.
  • Use this as a lead. Confirm important actions with shell history, audit logs, application logs, or change tickets when available.

To check successful logins

last

Shows recent successful login sessions.

To check current logged-in users

w

Shows who is logged in and what they are doing.

To check failed SSH login attempts

grep "Failed password" /var/log/auth.log

Shows failed SSH/password login attempts on Debian/Ubuntu systems.

Patterns and variants
  • Change the quoted pattern when your distro or service logs different wording.
  • Use grep -i "failed password" /var/log/auth.log for case-insensitive matching.
  • Use grep "Failed password" /var/log/auth.log | tail -n 20 to focus on recent matches.
  • On some systems, SSH logs may be in /var/log/secure or the journal instead of /var/log/auth.log.

To check successful SSH logins

grep "Accepted" /var/log/auth.log

Shows successful SSH login attempts on Debian/Ubuntu systems.

Patterns and variants
  • "Accepted" commonly matches successful SSH authentication lines.
  • Use grep "Accepted publickey" /var/log/auth.log to focus on key-based logins.
  • Use grep "Accepted password" /var/log/auth.log to focus on password logins.
  • Confirm unusual logins with last, w, and service logs.

To follow a log file live

tail -f /var/log/auth.log

Shows new log lines as they are written.

Flags and values
  • -f follows appended lines.
  • Change the path to the log you need, such as /var/log/syslog, /var/log/nginx/access.log, or an application log.
  • Use tail -n 100 -f file_name to show recent context before following.
  • Stop with Ctrl+C.

To review shell history

history | tail -n 50

Shows the last 50 commands from the current user's shell history.

Values and caution
  • Change -n 50 to the number of commands you need.
  • History may be incomplete, disabled, edited, or split across shells.
  • Do not treat shell history alone as proof. Use it as a lead with logs and timestamps.

Optional Phase 9: Packages and Application Checks

Goal: check whether a command exists, where it is located, and what package/application is installed.

Flags and values to adjust for package and command checks
  • command_name is a placeholder for a binary such as python, curl, nmap, ss, or tcpdump.
  • command -v is usually better for scripts because it is shell-aware and predictable.
  • apt list --installed can be noisy. Pipe to grep or use apt-cache policy package_name for one package.
  • Package commands differ by distro. Debian/Ubuntu use apt and dpkg; Fedora/RHEL often use dnf and rpm.

To check if a command exists

which command_name

Shows the path of a command if it exists in the system PATH.

Values and caveat
  • Replace command_name with the command you need, such as curl or python3.
  • which is useful interactively, but command -v is usually safer in scripts.

To check command location more reliably

command -v command_name

Shows how the shell resolves a command.

Values and variants
  • Replace command_name with the binary or shell command you are checking.
  • Use command -v command_name >/dev/null in scripts when you only need success or failure.
  • Use type command_name when you want to know whether something is a binary, shell builtin, function, or alias.

To find related binary, source, and manual paths

whereis command_name

Shows common locations related to a command.

Values and variants
  • Use this when you want binary, source, and man page locations in one quick check.
  • Use whereis -b command_name to show binaries only.
  • Use man command_name when you need full documentation.

To check installed packages on Debian/Ubuntu

apt list --installed

Lists installed packages on Debian/Ubuntu systems.

Flags and variants
  • --installed filters to installed packages.
  • Use apt list --installed | less when reviewing interactively.
  • Use dpkg -l for the classic package table format.

To search installed packages on Debian/Ubuntu

apt list --installed | grep package_name

Checks whether a specific package is installed.

Values and variants
  • Replace package_name with the package or keyword you are checking.
  • Use grep -i package_name for case-insensitive matching.
  • Use apt-cache policy package_name to check installed and candidate versions for one package.
  • Use dpkg -L package_name to list files installed by a package.

To inspect package details on Debian/Ubuntu

apt show package_name

Shows package description, version, dependencies, maintainer, and repository information.

Values and variants
  • Replace package_name with the package you are reviewing.
  • Use this before installing a package so you understand what it is and where it comes from.
  • Use apt search keyword when you do not know the exact package name.

Optional Phase 10: Secure Transfer and Evidence Handling

Goal: move files safely and keep basic integrity records.

Flags and values to adjust for transfer and evidence
  • tar -czf archive.tar.gz folder_name: -c creates, -z compresses with gzip, and -f names the archive file.
  • scp: replace local file paths, remote usernames, hosts, and destination paths carefully. Use uppercase -P for a custom SSH port.
  • rsync: use when transfers may be interrupted or repeated. It can resume and only copy changes.
  • sha256sum: hash files before and after transfer when integrity matters. Store hash files with your notes.

To compress a folder

tar -czf archive.tar.gz folder_name

Creates a compressed archive of a folder.

Flags and values
  • -c creates a new archive.
  • -z uses gzip compression.
  • -f archive.tar.gz sets the output file name. The archive name must come right after -f.
  • Replace folder_name with the folder you want to archive.
  • Use tar -czvf archive.tar.gz folder_name if you want verbose output.

To extract a compressed archive

tar -xzf archive.tar.gz

Extracts a gzip-compressed tar archive into the current directory.

Flags and values
  • -x extracts an archive.
  • -z handles gzip compression.
  • -f archive.tar.gz selects the archive file.
  • Use tar -tzf archive.tar.gz to list contents before extracting.
  • Use tar -xzf archive.tar.gz -C destination_folder to extract into a specific folder.

To copy a file securely to another system

scp file_name user@host:/path/

Transfers a file securely over SSH.

Values and variants
  • Replace file_name with the local file.
  • Replace user, host, and /path/ with the remote account, system, and destination.
  • Use scp -P 2222 file_name user@host:/path/ for a custom SSH port.
  • Use scp -r folder_name user@host:/path/ to copy a directory recursively.

To download a file securely from another system

scp user@host:/path/file_name .

Downloads a file from a remote system over SSH.

Values and variants
  • The final . means download into the current directory.
  • Replace it with a local folder path when you want a specific destination.
  • Use quotes around remote paths that contain spaces.
  • Use scp -P 2222 user@host:/path/file_name . for a custom SSH port.

To sync files with resume-friendly behavior

rsync -avP source_path user@host:/path/

Copies files over SSH while preserving useful metadata and showing progress.

Flags and values
  • -a uses archive mode for recursive copying and metadata preservation.
  • -v prints what is happening.
  • -P combines progress output and partial transfer handling.
  • Use --dry-run first when syncing important folders.
  • Be careful with trailing slashes: source/ copies contents, while source copies the directory itself.

To verify file integrity

sha256sum file_name

Creates a hash that can be used to confirm the file did not change.

Values and workflow
  • Run sha256sum file_name > file_name.sha256 before transfer.
  • Transfer both the file and the .sha256 record.
  • Run sha256sum -c file_name.sha256 after transfer to verify integrity.
  • Record the hash, filename, timestamp, and system name when handling evidence.
